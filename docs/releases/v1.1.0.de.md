# Codex Viewport 1.1.0

**A self-hosted web remote for Codex.**

[English](v1.1.0.md)

Codex Viewport führt den neuen Namen durchgehend in Browseroberfläche, Repository, Wiki, Paketmetadaten, Docker-Beispielen und Konfiguration ein. Das bereitgestellte Logo hat jetzt einen transparenten Hintergrund. Die Anmeldung zeigt die Wortmarke, Seitenleiste, Chat und Favicon das Bildzeichen. Im Dark Mode wird die Darstellung für bessere Lesbarkeit aufgehellt.

Repository: `Tweak90/codex-viewport`. Container-Image: `ghcr.io/tweak90/codex-viewport-ui:1.1.0` oder `latest`. Lokales Image im Docker-Archiv: `codex-viewport:1.1.0`. Kompatibilität bleibt mit Codex 0.166.0 und Node.js 22 verifiziert; ausschließlich die externe WebSocket-API wird unterstützt.

## Update vorbereiten

Diese Version ändert technische Bezeichner. Das Deployment führt der Betreiber separat aus; die Veröffentlichung startet oder verändert keine vorhandene Installation.

- Das bisherige Web-Datenvolume sichern und ausdrücklich weiterverwenden. Für Compose `CODEX_VIEWPORT_VOLUME` auf dessen tatsächlichen Docker-Namen setzen. Der neue Standard `codex-viewport-data` würde bei einer bestehenden Installation ein anderes Volume verwenden und die Ersteinrichtung statt der vorhandenen Daten zeigen. Das bisherige Volume nicht löschen und bei der Prüfung kein neues Produktionspasswort setzen.
- Neue Repository- und Image-URLs verwenden. Eine gespeicherte Überschreibung des Release-Repositorys leeren oder auf `Tweak90/codex-viewport` setzen.
- Die Sprache über `CODEX_VIEWPORT_LANGUAGE` (`en` oder `de`) und das Image über `CODEX_VIEWPORT_IMAGE` konfigurieren. Die Sprache nach dem Update erneut prüfen; ausgemusterte Konfigurationsnamen bleiben nicht als Aliase bestehen.
- Compose verwendet den Projektnamen `codex-viewport`. Vor dem Wechsel die bisherigen Projekt-/Containernamen prüfen, damit beim Deployment nicht versehentlich zwei Anwendungen laufen. Unabhängig vom Projektnamen das vorhandene Web-Datenvolume weiterverwenden.
- Neue Anhänge liegen unter `.codex-viewport/uploads/` im jeweiligen entfernten Projekt. Bisherige Anhänge behalten ihre gespeicherten absoluten Pfade und werden durch diese Version weder verschoben noch gelöscht.

Historische Git-Commits, Tags und bisherige Releases bleiben erhalten. Downloads enthalten Quellcode, ein Linux/amd64-Docker-Archiv und SHA-256-Prüfsummen. Umgebungsdateien, Zugangsdaten, Laufzeitdaten und Nutzer-Screenshots sind nicht enthalten.

Geprüft: 44 API-/Transport-/Veröffentlichungstests, 25 isolierte Browsertests, Übersetzungs- und Dokumentationsprüfung, beide Compose-Konfigurationen und Docker-Build erfolgreich.
