# Codex Viewport 1.0.1

[Deutsch](https://github.com/Tweak90/codex-viewport/blob/main/docs/releases/v1.0.1.de.md)

Project agents, clearer settings and an external-API-only web client.

- **Settings:** one sidebar entry above usage limits, with General, Codex and Updates categories. English is the default without ENV or a saved language. Useful defaults, source markers and saved overrides are explicit; **Use default** restores the underlying configuration. Technical ENV details expand per field, edits survive category changes, and Save/Cancel stay visible.
- **Info:** an informational GitHub release check shows new-version availability, version and publication date. The web container requests public release metadata directly over HTTPS without authentication by default. Optional credentials support private repositories. The check needs no Codex-host command or Docker access and never installs an update. Notification/sound controls and the panel-reset action are removed.
- **Allowances:** only two remaining percentages appear below the activity-bar usage icon: 5-hour first, weekly second. Missing values stay unknown; live quota events update the display.
- **Agents:** project-scoped active and previous subagents, archived histories, search/status filters, parent-chat navigation and output in 20-entry pages. Reading never starts or resumes agent work.
- **Branding and themes:** the selected blue/cyan terminal logo has a transparent background throughout the UI, chat, favicon, README and Wiki. Cached UI references refresh. Open select menus use readable foreground/background colors in both themes.
- **External API only:** the client connects using `ws://` or `wss://`. Local transport, host-start components and their configuration are removed. Retired saved settings migrate automatically. The web UI can start before an API address is supplied in ENV or Settings.
- README, installation, configuration, architecture and usage guides are updated in German and English.


Compatibility: Codex 0.166.0, Node.js 22, Linux/amd64 image. Validation includes 44 API/transport/publication tests, 25 isolated browser tests, documentation/translation checks, Compose validation, Docker build and desktop/mobile visual review. Tests do not consume model requests or real quota resets.
