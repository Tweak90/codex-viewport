# Codex Viewport 1.1.0

**A self-hosted web remote for Codex.**

[Deutsch](v1.1.0.de.md)

Codex Viewport introduces the new product identity throughout the browser interface, repository, Wiki, package metadata, Docker examples and configuration. The supplied logo now has a transparent background; sign-in uses the full wordmark, while the sidebar, chat and favicon use its symbol. Dark mode brightens the displayed logo for readability.

Repository: `Tweak90/codex-viewport`. Container image: `ghcr.io/tweak90/codex-viewport-ui:1.1.0` or `latest`. Local Docker archive image: `codex-viewport:1.1.0`. Compatibility remains verified with Codex 0.166.0 and Node.js 22; the only transport is an external WebSocket API.

## Upgrade preparation

This release changes technical identifiers. The operator performs deployment separately; publishing does not restart or change an existing installation.

- Back up and explicitly reuse your existing web data volume. Set `CODEX_VIEWPORT_VOLUME` to that volume's actual Docker name when using Compose. The new default is `codex-viewport-data`; accepting it on an existing installation creates a different volume and shows first-run setup instead of existing data. Do not delete the existing volume or set a new production password during verification.
- Use the new repository and image URLs. If a saved release-repository override exists, clear it to use the new default, or set it to `Tweak90/codex-viewport`.
- Set language with `CODEX_VIEWPORT_LANGUAGE` (`en` or `de`) and image selection with `CODEX_VIEWPORT_IMAGE`. Review the language setting again after upgrading; retired configuration names are not retained as aliases.
- Compose uses the project name `codex-viewport`. Inspect the current installation's project/container names before switching so deployment does not accidentally leave two applications running. Retain the existing web data volume regardless of the project name.
- New attachments use `.codex-viewport/uploads/` in each remote project. Existing attachments keep their recorded absolute paths and are not moved or deleted by this release.

Historical Git commits, tags and previously published releases remain available. Downloads include a source archive, a Linux/amd64 Docker archive and SHA-256 checksums. No environment files, credentials, runtime data or user screenshots are included.

Validation: 44 API/transport/publication tests, 25 isolated browser tests, translation and documentation checks, both Compose configurations and a Docker build passed.
